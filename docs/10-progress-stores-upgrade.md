# Переход на явный выбор progress-store

Изменения относятся к компоненту Queue. Миграции БД не нужны, интерфейсы
`ProgressStoreInterface` и `QueueProgressSnapshot` не изменены. Прямое создание
`DatabaseProgressStore`, существующий `Worker` и передача `progressStore: null`
остаются совместимыми. Версию выпуска выбирает сопровождающий пакета.

## Что можно заменить в интеграции

Если раньше приложение создавало анонимную заглушку `ProgressStoreInterface`,
теперь доступны `NullProgressStore` и `Drivers\InMemoryProgressStore`.
Для конфигурационного выбора используйте `ProgressStoreFactory::create()`.
Он принимает массив секции queue и необязательный `ConnectionManagerInterface`.

1. Настройте `progress_driver` независимо от драйвера очереди.
2. Для раздельных HTTP/worker выберите `database`. Сохраните прежние
   `progress_connection` и все переопределения `progress_schema`.
3. Для локальных сценариев выберите `memory` и передавайте всем потребителям
   один экземпляр. Два вызова фабрики создают два независимых store.
4. Для намеренного отключения прогресса и отмены выберите строку `'null'`.
5. Если `progress_driver` не указан, фабрика выбирает `database`. Тесты без БД
   должны явно выбрать `memory` или `'null'`.
6. При некорректных настройках фабрика бросает `InvalidArgumentException`, при
   ошибках SQL хранилище сохраняет прежнее поведение исключений — нет тихого fallback.

Не связывайте эту настройку с `FailedJobStoreInterface`: хранение неуспешных заданий
настраивается отдельно. Фабрика прогресса не валидирует и не создаёт саму очередь.

## Исправления DB-store

- `setProcessed()` с `percent=null` или отрицательным процентом записывает `0`, а не
  SQL NULL. Это устраняет нарушение NOT NULL при неизвестном/нулевом total у reporter.
- Запрос отмены выполняется атомарно. Повтор в ту же секунду больше не пытается
  вставить существующий `job_id` из-за нулевого affected rows. Конкурентные отмены
  используют уникальный индекс задания; остальные поля результата не сбрасываются.
- Время берётся из общего Clock. При заморозке времени в тестах отметки store теперь
  также заморожены. Без заморозки формат и timezone остаются прежними.

Добавлена runtime-зависимость `phpsoftbox/clock`; TestUtils не нужен для работы пакета.
После обновления пакета долгоживущие worker должны получить новый код штатным
перезапуском. Никакого автоматического повторного запуска бизнес-заданий компонент
не выполняет.

Подробный контракт и примеры: [прогресс и отмена](08-progress.md).
